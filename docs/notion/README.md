# 이 프로그램의 노션 문서

프로그램의 소스는 기존 위치에서 관리합니다. 이 폴더는 설명과 변경 기록만 보관합니다.

## 수정할 때
1. 기존 작업 지침과 `project.json`, `current.md`, 최근 이력을 읽습니다.
2. 의미 있는 수정·출시·수리 단위로 `current.md`를 현재 상태에 맞게 고칩니다.
3. `history/날짜-순번.md`와 같은 이름의 `.json`을 추가합니다. 과거 파일은 수정하거나 지우지 않습니다.
4. 실제 변경 위치, 이유, 확인한 결과, 실행·현장 적용 여부, 남은 문제와 기준 커밋을 기록합니다. 시험하지 않은 결과는 ‘확인 기록 없음’으로 적습니다.
5. 기본 브랜치에 반영하면 `Notion documentation`이 검사하고 고정 페이지를 갱신합니다. 코드를 저장하기만 한 중간 단계는 게시하지 않습니다.

공용 작성 규칙: https://github.com/sujungwin8-cpu/notion-project-sync/blob/v1/RULES.md

## 문서 위치
- `project.json`: 변경하지 않는 프로젝트 ID·유형·연결 페이지, 추적할 소스 범위
- `current.md`: 현재 기능, 실행 방법, 연결·설정, 남은 작업
- `manual.md`: 상세 사용설명서. `project.json`의 `manual_file`로 등록하면 노션의 현재 상태 안에 펼침 항목으로 게시됩니다. 설명서 변경 시 현재 문서와 새 이력도 함께 남깁니다.
- `history/*.md`: 수정 한 번의 설명
- `history/*.json`: 기록 ID, 날짜, 제목, 버전, 적용 상태, 기준 커밋 링크

노션 페이지 상단의 쉬운 설명과 현장 메모는 직접 고쳐도 보존됩니다. 자동 관리 상자 내부는 GitHub에서 수정합니다. 노션에서 고친 내용이 GitHub로 자동 반영되지는 않습니다.

## 새 저장소를 처음 연결할 때
공용 저장소의 `tools/scaffold.py`로 초안을 만들고, 모든 ‘작성 필요’ 내용을 실제 확인한 설명으로 교체합니다. 노션 데이터베이스에 프로그램별 독립 게시물을 하나 만들고 해당 연결에 이 게시물의 접근을 허용합니다. 여러 프로그램을 한 게시물 아래에 넣지 않습니다. 이 저장소 Actions secret에 `NOTION_TOKEN`을 한 번 등록합니다. 그 뒤에는 같은 게시물과 공용 자동화를 계속 씁니다.

노션 `프로그램 구분` 선택 속성은 `kind: installation`이면 **수리 프로그램**, `kind: software`이면 **개발 프로그램**으로 등록합니다. `프로젝트 ID`와 `GitHub 저장소` 속성도 함께 채웁니다. 이 분류는 최초 등록 시 지정하며 이후 본문 게시가 덮어쓰지 않습니다. 실제 프로그램 종류가 달라지는 경우에는 기존 고정 ID 규칙에 따라 별도 이관을 진행합니다.

매장 시스템 여러 개를 한 저장소에서 관리할 때는 `projects/<고정 ID>/project.json`으로 각각 등록할 수 있습니다. 그 경우 호출 워크플로의 경로 조건에 `projects/**`를 포함하세요.
